# Versioning Policy

The project follows **Semantic Versioning (SemVer)**.

```
MAJOR.MINOR.PATCH
```

Examples:

```
1.0.0

1.1.0

1.1.1

2.0.0
```

### MAJOR

Breaking changes.

---

### MINOR

New features without breaking compatibility.

---

### PATCH

Bug fixes and small improvements.

---

# Changelog Rules

Every release must include:

- Added
- Changed
- Fixed
- Removed
- Deprecated
- Security

Only user-visible or developer-relevant changes should be recorded.

# Notes

The changelog should be updated for every release.

Each entry must clearly describe **what changed**, **why it changed**, and **which version introduced the change**.

Maintaining an accurate changelog helps developers, testers, and users understand the evolution of the MowiShift platform.
